RAG∞ Ultimate — complete workflow, deployment & testing guide

Written for beginners. Follow the sections in order: install on your Windows PC, check it works, publish the code to GitHub, put the app online on Streamlit Community Cloud and/or a Hugging Face Docker Space, and then test every feature with the checklists. Each test says exactly what to do and what you should see.

Commands are for Windows PowerShell. On macOS/Linux replace py with python3 and \ with /. Every grey box has a Copy button.

0. What this is & the big picture

RAG∞ Ultimate is a web app that answers questions from your own documents (PDFs, Word, Excel, images…). It finds the exact passages, writes an answer that uses only those passages, adds a citation for every fact, and checks the numbers before showing them. If the answer is not in your documents, it says so instead of guessing.

How a question is answered

Where things live

💻 Your PC

The project folder, your .env file with the keys (secret, never uploaded) and a local test copy of the app at http://localhost:8501.

🐙 GitHub

A copy of the code (no keys). Streamlit Cloud reads it from here and redeploys itself after every push.

🎈 Streamlit Community Cloud

Free online app. Keys are pasted into its Secrets.

🤗 Hugging Face Space

Online app built from a Docker image (2 vCPU, 16 GB RAM). Needs a Hugging Face PRO account to create. Keys live in Variables and secrets.

🐘 Neon PostgreSQL

Online database for accounts, chats, permissions and the audit log, so they survive restarts.

🗄 Hugging Face dataset

A private storage repo where the online app keeps uploaded documents' search indexes, so they survive restarts.

⚡ Groq

Fast AI models that write the answers (main + 3 fallback models, plus backup keys).

🔀 OpenRouter

Free AI models: a last-resort text model and the image (vision) models.
Why online servers need Neon and a datasetStreamlit Cloud and Hugging Face wipe their disk every time the app restarts or sleeps. Anything stored only on that disk disappears. Neon keeps accounts and chats; the Hugging Face dataset keeps the documents.

3. Get your keys & accounts

Treat every key like a password.Paste keys only into the setup questions, your .env file, Streamlit Secrets or Hugging Face Secrets. Never into chat messages, screenshots or GitHub.

3.1 Groq key (answers)

  1. Open console.groq.com and sign inGoogle or e-mail login is fine.
  2. API Keys → Create API KeyName it rag. Copy the key (starts with gsk_). It is shown only once.
  3. Optional: backup keysCreate up to 2 more keys (better: from a second Groq account). When a key hits its rate limit, the app automatically repeats the request with the next key.

3.2 OpenRouter key (free backup + images)

  1. Open openrouter.ai and sign in
  2. Keys → Create KeyCopy it (starts with sk-or-). Optional backup keys work the same way.
  3. Settings → PrivacyIf free models are refused later, allow the free-model data policy here.
CostThe default model chains use only Groq models and OpenRouter :free models, and a daily budget guard of $0.01 blocks paid models. You do not need a credit card.

3.3 Neon database URL (keeps accounts & chats online)

  1. neon.tech → Sign up → Create projectName rag, nearest region (e.g. Singapore / AWS ap-southeast-1 for India).
  2. Dashboard → ConnectCopy the connection string. It looks like postgresql://user:password@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
  3. Keep ?sslmode=require at the endNeon refuses connections without it.

3.4 Hugging Face token + dataset name (keeps documents online)

  1. huggingface.co/settings/tokens → Create new tokenType Write, name rag. Copy it (starts with hf_).
  2. Choose a dataset namee.g. YOURNAME/rag-ultimate-data. You do not create it yourself: the app creates it as a private dataset the first time it saves.

3.5 Admin login

Choose an admin username (e.g. admin) and a password of 10+ characters with letters and digits. The setup can also generate a strong one for you.

4. Install on your PC

  1. Unzip the projectRight-click rag-production-v1-2.2.2.zip → Extract All → e.g. D:\agents\RAG\. You get a folder rag-production-v1-main.
  2. Open PowerShell in that folder 
    cd D:\agents\RAG\rag-production-v1-main
    Tip: in File Explorer open the folder, click the address bar, type powershell, press Enter.
  3. Run the setup 
    py launch.py setup
    It creates a private Python environment (.venv), installs all packages (5–10 minutes), then asks the questions below. Keys are typed hidden: nothing appears while you paste — that is normal; press Enter.
  4. Answer the questions

5. Run & first check locally

5.1 Pre-flight check

py launch.py check --online

Each line is [ OK ], [WARN] or [FAIL] and says how to fix it. It checks the Python version, keys (shown only as “set / missing”), database connection, tables, OCR (Tesseract) and — with --online — lists the models your Groq/OpenRouter keys can see (uses no tokens).

OCR on Windows (optional)Text inside scanned PDFs/images needs Tesseract: install it from github.com/UB-Mannheim/tesseract/wiki and tick “Add to PATH”. Online apps already include it.

5.2 Start the app

py launch.py run

Your browser opens http://localhost:8501. Log in with the admin account. Stop the app with Ctrl+C in PowerShell.

py launch.py run --api        # also starts the REST API at http://localhost:8000/docs

5.3 Five-minute smoke test

  1. Guide & Test Lab → ① Start hereAll dots green or yellow (yellow = optional).
  2. ③ Test Lab → 📥 Load sample documents4 sample documents become ready.
  3. Chat → ask What is the peak output current? → 2.2 A, citation to page 2, ✓ Verified.
  4. Ask it again → marked as cached, almost instant.
  5. Test Lab → ▶ Run safety tests → all rows ✅.

If these pass, your installation is good. The full test plan is in sections T1–T16.

7. Deploy to Streamlit Community Cloud (free)

  1. Make the secrets text 
    py launch.py secrets
    This writes .streamlit\secrets.toml (git-ignored) from your .env and warns about anything unsafe (no login, no online database…).
  2. share.streamlit.io → sign in with GitHub → Create app → Deploy a public app from GitHub
  3. Fill in the formRepository YOURNAME/rag-v2 · Branch main · Main file path app.py · choose an App URL.
  4. Advanced settingsPython version 3.12. Open notepad .streamlit\secrets.toml, copy everything, paste into Secrets.
  5. DeployThe first build takes ~5 minutes (it installs requirements.txt and the system packages in packages.txt, including Tesseract OCR).
  6. Log in and run the smoke test (5.3)
Change settings latershare.streamlit.io → your app → ⋮ → Settings → Secrets → edit → Save (the app restarts). Logs: ⋮ → Manage app (bottom-right of the app page).
LimitsSmall memory (very large PDFs or many users at once can make it restart) and it sleeps after a few hours without visitors — the first visitor wakes it in under a minute.

8. Deploy to a Hugging Face Docker Space

Paid plan needed to create itSince 2026 Hugging Face lets only PRO accounts (≈ $9/month) create Docker Spaces; free accounts get 402 Payment Required. The Space then runs on the free CPU Basic hardware (2 vCPU, 16 GB RAM) — do not choose paid hardware.
  1. Build and upload with one command (replace MVSPC16 with your username) 
    py launch.py spaces --push MVSPC16/rag-ultimate
    It builds build\hf-space (code only — never .env, data or tests), creates a private Docker Space, sends your .env values as Space secrets (keys, passwords, tokens, DATABASE_URL) and variables (everything else, with LLM_MODE=cloud), and uploads the files. If asked, paste a Write token.
  2. Watch the build (5–10 min)Open the printed link → Logs. Build tab = installing; Container tab should show 
    RAG Ultimate on Hugging Face Spaces: DATA_DIR=... LLM_MODE=cloud
applied: [...]
  3. Check the database lineIf the Container log says WARNING: DATABASE_URL is not reachable from this Space -> using SQLite, Hugging Face blocked the connection to Neon: the app works but accounts/chats are not kept after a restart (see Troubleshooting).
  4. Status “Running” → log in → smoke test (5.3)
  5. Make it public (optional)Settings → Change Space visibility. Only after AUTH_MODE=users is set. Then open the link in a private window: you must see only the login screen.

9. Keep the Streamlit and Hugging Face apps separate

Both apps run on different servers, but if both use the same DATABASE_URL and HF_DATASET_REPO they share accounts, chats and documents — and two apps writing the same document files can overwrite each other. Give one of them its own storage:

  1. Neon: second databaseNeon → your project → Databases → New database → e.g. rag_streamlit. Copy its connection string.
  2. Streamlit → ⋮ → Settings → SecretsChange these two lines and Save: 
    HF_DATASET_REPO = "MVSPC16/rag-data-streamlit"
DATABASE_URL = "postgresql://...neon.tech/rag_streamlit?sslmode=require"
  3. OptionalGive each app its own Groq/OpenRouter keys so they do not share rate limits.

How to confirm: upload a test PDF in the Streamlit app → it must not appear in the Hugging Face app; a user created in one app cannot log in to the other; your HF profile shows two datasets.

10. Docker on your own PC or server (optional)

Runs the UI, the REST API and a PostgreSQL database in containers. Start Docker Desktop first, then add a database password to .env:

POSTGRES_PASSWORD=choose-a-long-password
py launch.py docker up --profile cloud      # UI + API + PostgreSQL (cloud AI models)
py launch.py docker status
py launch.py docker logs
py launch.py docker backup                  # database backup into .\backups
py launch.py docker down

App: http://localhost:8501 · API: http://localhost:8000/docs. Other profiles: hybrid (adds Ollama local models), local (fully offline), production (HTTPS proxy, MinIO, monitoring — see docs/DEPLOYMENT_GUIDE.md).

14. Glossary

RAGRetrieval-Augmented Generation: search your documents first, then let the AI write an answer from what was found.
Chunk / passageA small piece of a document (a paragraph, a table, a figure) that the search can return.
Citation [REF-2: TABLE p3]Evidence number 2, a table on page 3.
Verified ✓Every number in the answer was found in the cited evidence.
Fallback modelThe next model tried when one fails, is rate-limited or is unavailable.
Backup keyA second/third API key tried before switching model when a key is rate-limited or rejected.
Answer cacheStores verified answers so the same question (same documents, filters, settings) is answered instantly without AI cost.
MetadataDetails about a document (title, category, part numbers, parameters with units), with where each came from.
Tenant / workspaceAn organisation / a user's private area; data never crosses between them.
.envThe private settings file on your PC with keys and options. Never upload it.
Secrets / variablesThe online equivalent of .env on Streamlit Cloud and Hugging Face (secrets are hidden).
Docker / SpaceA packaged, ready-to-run copy of the app; a Space is Hugging Face's hosting for it.
NeonHosted PostgreSQL database service.
