RAG Ultimate 2.0: step-by-step guide

From "I have a ZIP file" to a running, secure document-question-answering app, first on your own computer, then on a server. Every command is copy-paste ready. Tick each step as you finish it; your progress is remembered in this browser.

Pick your operating system once using any tab like Windows macOS Linux; all other tabs on the page switch with it.

0 · What you are building

You upload documents (PDF, Word, PowerPoint, Excel, CSV, text, Markdown, HTML, JSON, images). You ask questions in plain English. The app finds the exact passages, asks an AI model to answer only from those passages, checks every number against the cited source, and shows you the evidence.

1 · Install the tools

One-time setup. If a tool is already installed, skip its step.

1

Install Python 3.12 (or 3.13)

Download from python.org/downloads, run the installer and tick "Add python.exe to PATH" on the first screen. Then open PowerShell (Start menu → type "PowerShell") and check:

python --version

Install Homebrew if you don't have it, then:

brew install python@3.12
python3 --version
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
python3 --version

You should see Python 3.12.x or 3.13.x.

2

Install Tesseract (reads text from images and scans)

Download the installer from github.com/UB-Mannheim/tesseract/wiki and install it to the default folder C:\Program Files\Tesseract-OCR. Then add it to PATH (PowerShell, one line):

[Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\Program Files\Tesseract-OCR", "User")

Close and reopen PowerShell, then check:

tesseract --version
brew install tesseract
tesseract --version
sudo apt install -y tesseract-ocr
tesseract --version
Optional: without Tesseract the app still works; images and scanned pages just won't be readable.
3

Install Git (needed later for GitHub)

Download from git-scm.com/download/win, accept the defaults.

git --version
brew install git
git --version
sudo apt install -y git
git --version
4

Choose an AI model source (you need at least one)

Option A: Ollama (local, private, free)
Runs the AI on your own computer. Needs about 8 GB RAM for an 8B model. Covered in Part 4.
Option B: Groq (cloud, free key)
Fastest way to try it. Create a free key at console.groq.com/keys and keep it ready (starts with gsk_).
With Option B your non-confidential document excerpts are sent to Groq. Documents you mark confidential (or that contain personal data) are never sent to a cloud model by default.

2 · First run on your PC

About 15 minutes, most of it waiting for downloads.

1

Unzip the project

Unzip rag-ultimate-2.0.0.zip into a simple folder, for example C:\projects (Windows) or ~/projects. You get a folder named rag-ultimate-main. Open a terminal in that folder:

cd C:\projects\rag-ultimate-main
cd ~/projects/rag-ultimate-main
cd ~/projects/rag-ultimate-main

Check you are in the right place: listing the folder (dir on Windows, ls elsewhere) shows app.py and requirements.lock.

2

Create a private Python environment ("venv")

This keeps the project's libraries separate from the rest of your computer.

python -m venv .venv
.venv\Scripts\Activate.ps1

If PowerShell says "running scripts is disabled", run this once, then the activate line again:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
python3 -m venv .venv
source .venv/bin/activate
python3 -m venv .venv
source .venv/bin/activate

Your prompt now starts with (.venv). Every time you open a new terminal for this project, run the activate line again.

3

Install the libraries 

python -m pip install --upgrade pip
pip install -r requirements.lock

Takes 3–10 minutes. requirements.lock holds exact, security-audited versions. Success ends with "Successfully installed …".

4

Create your settings file .env 

copy .env.example .env
notepad .env
cp .env.example .env
open -e .env
cp .env.example .env
nano .env

For the quickest first run, find the line GROQ_API_KEY= and paste your key after the = (no spaces, no quotes):

GROQ_API_KEY=gsk_your_key_here

Using Ollama instead? Leave it empty and do Part 4 first. Save and close the file.

Never share or upload .env: it holds your keys. It is already excluded from Git.
5

Start the app 

streamlit run app.py

Your browser opens http://localhost:8501. If it doesn't, open that address yourself. Keep the terminal window open while you use the app; press Ctrl + C in it to stop.

The first upload downloads two small local models (~150 MB, once) for meaning-based search. If you are offline, the app still works with keyword search and fills the gap automatically later.
6

Check that it works

  1. In the sidebar under Status, your model provider (Groq or Ollama) shows a green dot.
  2. Drop any PDF on the upload box, wait for "is ready".
  3. Ask: "Summarize this document". You get an answer with [REF-1: TEXT p2]-style citations and a ✓ Verified badge.
🎉 You now have a working RAG app. The rest of this guide is about using it well and running it for others.

New in 2.1

  • ❔ Help (top right of every page): type a question about using the app, e.g. how do I upload a file? — instant answers, no AI model, nothing stored. The same assistant is in Guide & Test Lab → ⑤ Help center.
  • Get started checklist at the top of Chat: four steps that tick themselves off as you do them.
  • ⚡ From cache: ask the same question again (even in other words) about the same documents and you get the earlier verified answer instantly and for free. It is never shared with other users or organisations, and a new document version clears it.

  • 🏷️ Metadata on every document card: title, category, tags, part numbers and technical values (e.g. VOUT = 5.0 V) found automatically, each with a confidence and the page it came from. Editors can correct them; search the library and use 🎚️ Filters in Chat to search only matching documents.

Sidebar controls

  • Model mode: local = only your Ollama, cloud = only cloud, hybrid = both.
  • Model: "Automatic (router)" or pick one exact model.

4 · Go fully offline with Ollama

Nothing leaves your computer: local AI, local search models, local database.

1

Install Ollama and download a model

Install from ollama.com/download. Then, in a terminal:

ollama pull llama3.1:8b
ollama pull nomic-embed-text
ollama list

llama3.1:8b (~4.7 GB) writes the answers; nomic-embed-text is optional, for local meaning-based search through Ollama. Low on RAM? Use qwen2.5:3b instead and put that name in OLLAMA_MODEL.

2

Point the app at Ollama

Edit .env and set:

LLM_MODE=local
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3.1:8b
EMBED_BACKEND=local

Restart the app (Ctrl + C, then streamlit run app.py). The sidebar shows Ollama (local) with a green dot.

3

Make it work with the network unplugged

While still online, upload one document once so the small search models download into data/models. After that you can disconnect. For machines that must never go online, copy the data/models folder from a machine that has them and set MODEL_DOWNLOAD=false.

5 · Turn on user accounts

Do this before anyone else uses your app. Without accounts, anyone who can reach the address can use it.

1

Enable accounts and set the first admin

In .env:

AUTH_MODE=users
ADMIN_USERNAME=admin
ADMIN_PASSWORD=ChooseAStrongPass123

Password rules: at least 10 characters with letters and digits. Username: lowercase letters, digits, . _ @ -. Restart the app; it now shows a sign-in screen. The admin is created automatically on first start.

2

Create users

Sign in as admin → Users & roles → Create user.

RoleCan
viewerAsk questions about documents they are allowed to read
editor+ upload, relabel and delete their own documents, run evaluations
adminEverything: users, policies, models, all documents, audit log

Five wrong passwords lock an account for 15 minutes. Disabling a user also revokes their API tokens.

3

Set the guardrail policy

Admin → Security. Defaults are safe; typical changes:

  • Allowed topics: limit the assistant to your domain, e.g. pump|valve and maintenance on separate lines.
  • Restricted topics: e.g. salary|compensation.
  • Usage limits: questions per minute and daily AI budget.

Use Test a prompt to see what would be blocked. Every block is recorded in the Audit log.

6 · Add cloud models (optional)

Add any of these keys to .env and restart. The router automatically uses what is configured and falls back to the next model if one fails.

GROQ_API_KEY=gsk_...            # free tier, fast text answers
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
OPENROUTER_API_KEY=sk-or-...     # used for reading figures / images
BEDROCK_REGION=us-east-1         # AWS; also: pip install -r requirements-optional.txt
LLM_MODE=hybrid                  # allow local AND cloud
The confidentiality rule (important)

Documents labelled confidential/restricted, or found to contain personal data, are answered by local models only. If no local model is configured, the app refuses rather than sending them to the cloud. Allow cloud for them only if your organisation agrees:

ALLOW_SENSITIVE_CLOUD=true
CLOUD_PROVIDERS_ALLOWED=anthropic

Cost/speed choice (ROUTING_STRATEGY): priority (your order, default), cost, latency, or auto (cheap/fast models for simple lookups, best model for calculations). Admins can see the live routing chain and why each model is excluded on the Models page.

9 · Measure answer quality with your real models

This step was not possible in the build environment, so do it once your models work. Keep the report as your quality baseline.

1

Retrieval benchmark (no AI cost) 

python -m evaluation.benchmark

Compares the old (1.x) search against the upgraded one on 18 known questions and prints precision, recall, MRR and NDCG. Reports are saved in data/evaluations/. Higher is better.

2

Full benchmark including answers (uses your AI) 

python -m evaluation.benchmark --generation

Adds answer correctness, faithfulness, citation correctness and hallucination rate. You can also run both from the Evaluation page and download Markdown/JSON/CSV reports.

10 · Put it on GitHub (and get automatic checks)

On github.com/new: name it e.g. rag-ultimate, choose Private, and do not add a README.

2

Push the project 

git branch -M main
git remote add origin https://github.com/YOUR-NAME/rag-ultimate.git

On GitHub → Actions. Jobs: lint, test (with a real PostgreSQL), dependency-audit, image (Docker build + smoke test + Trivy scan). All green = ready to deploy. A red job: click it to see the failing step. The image job is the first real Docker build of this project, so check it carefully.

11 · Production server with Docker (HTTPS, PostgreSQL, accounts)

For a team: a Linux server (Ubuntu 24.04, 4 vCPU, 16 GB RAM if running Ollama there; 2 vCPU / 4 GB with cloud models only) and a domain name.

1

Install Docker on the server 

curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER     # then log out and back in
docker compose version
2

Get the code onto the server 

git clone https://github.com/YOUR-NAME/rag-ultimate.git
cd rag-ultimate
cp .env.example .env
nano .env
3

Fill in the production settings 

AUTH_MODE=users
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<strong password>
POSTGRES_PASSWORD=<long random>
MINIO_ROOT_USER=ragstorage
MINIO_ROOT_PASSWORD=<long random, 8+ chars>

GROQ_API_KEY=...                 # and/or other providers, or OLLAMA_BASE_URL

Generate random passwords with openssl rand -base64 24.

4

Point your domain at the server

At your domain provider, create an A record: rag.yourcompany.com → your server's public IP. Open ports 80 and 443 in the server firewall. Caddy obtains the HTTPS certificate automatically.

5

Start everything 

docker compose --profile production up -d --build
docker compose --profile production ps

All services should show running / healthy after a minute or two. Open https://rag.yourcompany.com and sign in.

Run the smoke test against your server

From the server (the API is reachable on localhost:8000 there):

docker compose --profile production exec api \
  python -m scripts.smoke_test --api http://127.0.0.1:8000 --user admin --password '<admin password>'

7

Optional: monitoring dashboards

Grafana runs on the server at localhost:3000. Open it from your PC through an SSH tunnel: ssh -L 3000:localhost:3000 you@server, then http://localhost:3000. Sign in with admin and your Grafana password; the RAG Ultimate dashboard is pre-installed.

If docker compose up fails with "manifest unknown" for an image, that exact version tag was removed upstream. Edit the image: line in docker-compose.yml to a current tag and run the command again.

12 · Backups and daily operations

1

Make and verify a backup

On your PC (venv active):

python -m scripts.backup create --dest backups
python -m scripts.backup verify backups/rag-backup-YYYYMMDD-HHMMSS

On the Docker server:

docker compose --profile production run --rm backup

A backup folder holds the database, your data/ folder (indexes, originals, chats) and a checksum file.

2

Schedule it daily (server) 

crontab -e
# add this line (02:30 every night):
30 2 * * * cd /home/YOU/rag-ultimate && docker compose --profile production run --rm backup >> backups/cron.log 2>&1

Copy the backups/ folder to another machine or cloud storage regularly. MinIO files: back up with mc mirror.

3

Practise a restore once 

python -m scripts.backup restore backups/rag-backup-YYYYMMDD-HHMMSS
Restore replaces the current database and data folder. It asks for confirmation first.

13 · How it works inside (the complete workflow)

You don't need this to use the app, but it explains what happens to every file and every question.

A. When you upload a document

1 ValidateReal file type checked by its bytes (not the name); size limit; rejects executables, macro Office files, zip bombs
→
2 Store originalKept by content fingerprint (local folder or MinIO/S3); identical files stored once
→
3 ReadPDF: text, tables, equations, figures. Office/HTML/CSV/JSON: own readers. Images and scans: Tesseract OCR
→
4 ChunkSplit into passages (recursive, fixed, semantic or structure strategy), each keeps its page and section
→
5 EmbedEach passage gets a "meaning vector" (local model or Ollama)
→
6 RegisterDatabase records document, version, chunks, sensitivity; PII found → auto confidential; older version's vectors removed

Failures are retried with increasing waits; a file that can never work (e.g. an executable) fails at once. Every attempt is visible on the Ingestion page.

B. When you ask a question

Every step is timed and shown on Agent traces; logs carry a request ID but never your question text.

C. How the model router picks an AI

  1. Start from the configured list (your manual choice first, then the priority order).
  2. Remove models that are: not configured · wrong for the mode (local/cloud) · cloud while the documents are confidential · too small for the text · recently failing (circuit breaker).
  3. Order what is left by the strategy (priority, cost, latency or auto).
  4. Try the first; on a temporary error retry, then move to the next. The reason is shown under Why this model.

D. Security layers at a glance

Files
type sniffing, size limit, macro/zip-bomb/executable rejection
Questions
prompt injection, harmful content, topic rules, personal-data redaction
Documents as data
instructions hidden inside documents are neutralised, never obeyed
Access
accounts, roles, tenants, per-document roles, retrieval-time filtering
Answers
grounding check, abstention, secret and prompt-leak filtering, PII masking
Records
audit log of blocks, logins, uploads, deletions, policy changes
These detectors are rule-based. They block common attacks but can miss clever new ones, and occasionally block an innocent question. Treat them as strong seat belts, not a guarantee (details: docs/SECURITY_AUDIT.md).

16 · Glossary

RAGRetrieval-Augmented Generation: find relevant passages first, then let the AI answer from them.
ChunkA short passage of a document, the unit that is searched and cited.
EmbeddingA list of numbers describing a passage's meaning, so similar meanings can be found.
BM25Classic keyword search scoring; great for exact symbols and part numbers.
RRF / fusionCombines the rankings of several search methods into one list.
RerankerA small model that re-orders the top candidates by how well they answer the question.
OllamaFree program that runs AI models on your own computer.
Prompt injectionText that tries to make the AI ignore its rules.
PIIPersonally identifiable information: e-mails, phone numbers, ID and account numbers.
TenantA separate organisation/space; nothing crosses between tenants.
venvA private folder of Python libraries for one project.
.envYour private settings file (keys, passwords, options).
Docker / Compose profilePackaged services; a profile is a named set of them started together.
CIAutomatic tests and scans that GitHub runs on every push.
